## Project

Group project (6 members) for DAM501. Chosen topic: **user behavior discovery and churn patterns for a subscription music service**, using the Kaggle competition dataset *WSDM – KKBox's Churn Prediction Challenge* (`kkbox-churn-prediction-challenge`). Chosen over Online Retail / Telco churn because another team already has an online-retail topic.

The brief grades discovery, not prediction: at least 2 mining techniques, at least 1 unsupervised or pattern-based (clustering, association rules, sequential patterns, anomaly detection). Classification (churn) is a supporting method only. Evaluate with silhouette/cohesion (clusters), support/confidence/lift (rules), and business actionability — not just accuracy/AUC.

Report structure (7 sections, weights): Business Understanding 15, Dataset 5, Pre-processing 10, EDA 15, Mining Methods 30, Evaluation 15, Business Insights 10; +10 bonus for advanced techniques (feature engineering, PCA/UMAP, subset comparison). Deliverables: report (PDF/Word), reproducible code with data prep / mining / analysis clearly separated, short presentation.

## Data constraints

- Leakage-safe design: cohort `feb` (train.csv, cutoff 2017-01-31) trains, cohort `mar` (train_v2.csv, cutoff 2017-02-28) tests out-of-time. Every feature must use data dated <= cutoff; `data/manifest.json` asserts this. Never add features from `transactions_v2`/`user_logs_v2` dated after the cutoff (they are only for `data_prep/03_build_leakage_audit.py`).
- `user_logs.csv.7z` (~7 GB) is never extracted: `data_prep/stream_logs.py` filters it while decompressing into `data/logs_window.parquet` (~2 GB).
- Keep the natural churn prior (~9 %); do not class-balance samples.
- pandas 3 and DuckDB 2: `astype(str)` keeps NaN, `groupby.apply` drops the key column, relations have no `fetchone()` (use `con.execute`).
- Set `PYTHONUTF8=1` on Windows (Vietnamese output).
- Clustering: users without listening logs are a rule-based segment; K-Means runs on 13 features (3 redundant ones dropped, |Spearman| > 0.8), k <= 7 chosen by silhouette + bootstrap ARI, never by churn. Segment names live in `report/segment_names.json` (ids must match the run).
- Known dirty columns: `bd` (age: 60 % invalid), `gender` (49 % missing).

## Layout

`data_prep/` (download, features per cohort, sequences, audit data) -> `analysis/` (EDA) -> `mining/` (01 clustering, 02 rules, 03 classification, 04 bonus, 05 sequential, 06 leakage audit, 07 temporal stability, 08 calibration/profit, 09 model improvement, 10 7-aspect evaluation, 11–13 sensitivity analyses) -> `report/`. All scripts read `data/features_<cohort>.parquet` via `mining/common.py`. Smoke-test with synthetic data: `python tests/make_synthetic_data.py data_synth` then `DATA_DIR=data_synth REPORT_DIR=report_synth python run_all.py --skip-download`.
